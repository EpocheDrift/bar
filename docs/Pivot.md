## 新方向：像素风 AI 酒吧

### 核心概念

用户打开页面，进入一个**像素风格的酒吧场景**。吧台后面站着一个以朋友真实形象为原型的**像素风酒保**，该酒保背后接入 AI Agent。用户可以直接和酒保对话，酒保根据用户的心情、口味、偏好推荐鸡尾酒，并有自己的性格和语气。

### 创意核心（必须有）

1. **场景感** — 用户感觉"进入"了一个像素风酒吧，而不是打开了一个网页应用
2. **AI 酒保角色** — 有真实人物原型的性格，不是普通 chatbot

### 9天内最小可行版本

**Lisa（设计）负责：**
- 像素风酒吧背景图（静态）
- 酒保角色 sprite（静态或 2帧 idle 动画）
- 整体视觉风格 + 像素字体选型

**Zayn（开发）负责：**
- 背景图 + 酒保 sprite 叠层布局
- AI 对话界面，样式融入像素风
- 酒保 system prompt（朋友的语气/性格）
- 最多 1 个额外交互元素（如点击某个酒瓶，自动带入对话）

### 暂缓到 Post-Deadline 的内容

- 多个可交互元素（酒瓶、吧台、酒架）
- 酒保动画（走动、调酒动作）
- 完整的场景互动系统

## 从旧版提炼的 Practical Needs

无论方向怎么变，以下四点是核心价值，需要在新版中以某种形式保留：

1. **配方发现** — 用户能通过某种方式（对话）得到一个鸡尾酒配方
2. **AI 推荐** — LLM 接入，基于用户输入给出个性化建议
3. **逐步引导** — 某种形式的 step-by-step 体验（可以通过对话实现）
4. **Web 可访问** — 浏览器直接打开，无需安装

---

## 技术栈决策

**放弃 Streamlit**，改用：

| 层 | 技术 | 原因 |
|---|---|---|
| 前端 | HTML / CSS / JS（或轻量框架） | 对像素风视觉和交互有完全控制权，不与 Streamlit 布局系统搏斗 |
| 后端 | Flask 或 FastAPI（极简） | 只做一件事：转发 AI API 调用 |
| AI | Minimax API 或 OpenAI（原有） | 沿用现有 key 和调用模式 |
