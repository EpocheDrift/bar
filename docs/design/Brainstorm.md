# Brainstorm — 用户旅程方向

> 状态：原料储备，尚未选定 · 最后更新：2026-05-27

---

## 背景

游戏核心是用户与 AI 酒保 Phoenix 的对话，交互元素（酒瓶等）作为辅助。
以下两个方向均有潜力，供后续设计决策参考。

---

## Direction A — 「氛围优先 / 开放式」

### 概念
没有固定流程。Phoenix 随意开口，用户可以聊任何事——今天过得怎么样、想喝什么、或者只是想随便说说话。Phoenix 根据整个对话的走向，在某个自然的时机说"我知道该给你做什么了"，推荐配方。用户随时可以离开，也可以继续聊。

### 感觉像
深夜和一个很懂你（但不一定对你好）的人坐着聊天。

### 优点
- 最自由、最有氛围感
- AI 发挥空间最大，对话可以去任何方向
- 符合 Phoenix 实际性格（自然随机，不按剧本走）

### 代价
- 用户可能不知道"该做什么"，需要 Phoenix 有能力引导而不显得刻意
- 对 system prompt 质量要求最高

### 9天可行性
✅ 中等，主要挑战在 Phoenix prompt 质量

---

## Direction B — 「仪式感 / 结构化旅程」

### 概念
每次进酒吧，体验一段有结构的旅程：

```
Phoenix 开口（冷淡/毫无表情）
  → 问你今晚的状态（一个开放问题）
  → 用户回答
  → Phoenix 问第二个问题（口味/方向）
  → 用户回答，或点击一个瓶子作为暗示
  → Phoenix "思考"（loading 动画）
  → Phoenix 宣布：这杯酒是为你做的
  → 配方出现（像一张卡片）
  → 可以继续聊怎么调，或离开
```

### 感觉像
一个技术很好但态度很差的调酒师在专门为你做一杯酒——你不确定她喜不喜欢你，但结果是对的。

### 优点
- 有完整弧线，用户体验到"完成感"
- Practical needs 全部自然满足
- 结构固定，开发更容易控制

### 代价
- 比 A 少一点随意性
- 对话状态需要管理（在哪个阶段问哪个问题）

### 9天可行性
✅✅ 最容易控制，适合 deadline 内交付

---

## 目前倾向

**A + B 混合**：B 的结构作为主干（保证完整体验），A 的自由度作为补充（Phoenix 不死板）。
具体混合方式待游戏设计会议确定。
