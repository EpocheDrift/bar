## G7 — Mixing Game 题目来源

**问题：** Mixing Game 的多选题（含错误选项）从哪里来？

| 方案 | 优点 | 缺点 |
|---|---|---|
| **A — AI 实时生成** | 题目每次不同，更有趣 | 依赖 AI 响应速度，增加一次 API 调用 |
| **B — 预烘焙进 JSON** | 速度快，稳定可控 | 需要人工准备错误选项内容 |

**结论：** 待定  
**影响：** G8（UI设计）、T3（游戏逻辑实现）

## G9 — Phoenix 触发 Mixing Game 的通信协议

**问题：** AI 只能输出文字，前端怎么知道"现在要切换到游戏模式"？

| 方案 | 优点 | 缺点 |
|---|---|---|
| **A — 特殊标记** Phoenix 回复里包含 `[GAME_START]`，前端检测后剥离并触发 | 精确，不误触发 | 需要 system prompt 严格约束 AI 输出格式 |
| **B — 关键词匹配** 前端检测到特定短语（"Let's find out" 等）就触发 | 更自然，不破坏 AI 输出 | 容易误触发，脆弱 |

**结论：** 待定（推荐 A）  
**影响：** T5（Flask 路由）、T6（前端游戏触发逻辑）

## T11 — 部署方案

**问题：** 作业提交时是本地跑 demo 还是要线上部署？

| 方案 | 优点 | 缺点 |
|---|---|---|
| **A — 本地 demo** | 零额外工作量 | 需要评分时有人在场跑服务 |
| **B — 线上部署** 前端 Vercel/Netlify + 后端 Render/Railway | 任何人随时访问 | 需要额外配置，约 2-4 小时 |

**结论：** 待定  
**影响：** T2（server.py 是否需要处理 CORS 等生产配置）

## T12 — Phoenix 知识库注入方式

**问题：** 如何把鸡尾酒配方知识给到 Phoenix AI？

| 方案 | 优点 | 缺点 |
|---|---|---|
| **A — 全量塞入 system prompt** | 实现最简单 | prompt 变长，token 成本高，可能影响性格表现 |
| **B — 摘要版塞入** 只放配方名+烈酒类型+口味标签 | prompt 紧凑 | Phoenix 无法给出详细步骤，需要额外处理 |
| **C — Tool call 按需查询** Phoenix 需要时调用 function 查 recipes.json | 最干净 | 实现复杂，增加延迟 |

**结论：** 待定（推荐 A，9天内最简单）  
**影响：** A1（system prompt 结构）、T5（Flask 路由预处理）
